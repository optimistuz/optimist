# CLAUDE.md — рабочие правила проекта (редакция 2.0, июль 2026)

## О проекте
Премиальный сайт сети салонов оптики «Оптимист» (Ташкент).
Два контура: **главная** — нарратив «путь пациента» (продаёт желание
и визит) и **витрина** — коллекции и страницы оправ (продаёт оправу
через визит в салон). Аудитория — средний Android (Galaxy A15/A54) на LTE.

### Иерархия документов
**Всегда основные — только два документа, и только они правятся
по ходу работ:**
1. **CLAUDE.md** (этот файл) — закон. При любом конфликте побеждает он.
2. **plan.md** — утверждённая дорожная карта v2.0: этапы 0–17 + хотфикс,
   треки, решённые развилки (§7 — НЕ пересматривать), дефолты и вопросы
   владельцу (§10). Работа ведётся ТОЛЬКО по нему.

Остальное — архив, по этапам НЕ правится и требованием не является:
**optimist.md** — замороженный снапшот архитектуры до-апгрейда (сверен
с `cadf8c6`; при расхождении верны CLAUDE.md и plan.md, свежее «как
устроено» — код); **PROJECT.md** — исторический
черновик ТЗ старого прототипа (ценны только факты: бренд с 2006,
контакты филиалов, палитра из логотипа, открытые вопросы: карта, языки);
**docs/research-v2/** — выходная папка агента `razvedchik`, **на сегодня
пуста**: отчёты появляются по мере заказанных исследований. Не ссылаться
на неё как на источник; в частности, отчёта `world-photoshoot` никогда
не существовало — полный shot-list живёт в `docs/photo-brief.md`.

### Переходное состояние (важно!)

## Агенты проекта (.claude/agents/)

Команда контролёров с широкими полномочиями. Основная сессия строит,
агенты контролируют. Вызов: инструментом Agent (subagent_type = имя)
или по просьбе владельца («позови физика»). Независимых агентов
запускай ПАРАЛЛЕЛЬНО одним сообщением.

⚠️ **Параллельность — про независимость ПРИБОРОВ, а не зон.** `hronometrist`
гасит dev и собирает прод (`next build` делит `.next` с `next dev`), `fizik`
меряет пиксели на живом dev; замер времени кадра под CPU 4× портит любой
второй браузер на той же машине. Такие агенты идут ПОСЛЕДОВАТЕЛЬНО, даже
если их зоны не пересекаются. Организовать параллельный прогон двум агентам,
делящим исключительный ресурс, — значит своими руками получить те самые
числа, ради перепроверки которых их и звали.

| Агент | Зона | Когда звать |
|---|---|---|
| `dirizher` | процесс, этапы, гейты, канон-коммиты | первым в начале и последним в конце каждой сессии |
| `fizik` | multiply/blend, VT, гидрация, фильтры, прелоадер | после любой правки рядом с оправами/переходами |
| `hronometrist` | бюджеты, вес, память, fps, A15/A54 | после любого нового веса/движения |
| `priyomshchik` | приёмка этапа по приборам + отчёт владельцу | перед закрытием этапа/полуэтапа |
| `revizor-vitriny` | каталог, воронка, честность, SEO | после правок каталога/воронки/заявок |
| `strazh` | приватность, право, бренд, слово (право вето) | правки данных клиента, текстов, фото, эстетики |
| `fotoceh` | конвейер фото-ассетов, нормализация, секвенции | при поступлении любых кадров |
| `razvedchik` | внешние исследования с источниками | когда нужны свежие знания извне |

### Стандартный цикл сессии
1. `dirizher` → бриф (этап, гейты, дефолты, канон-обязательства).
2. Основная сессия делает шаги этапа.
3. Параллельно по зонам касания: `fizik` + `hronometrist` +
   `revizor-vitriny` / `strazh` / `fotoceh`.
4. `priyomshchik` → приёмка + отчёт владельцу.
5. `dirizher` → закрытие (канон тем же коммитом, хвосты, план следующей).

### Как писать новых агентов
Файл `.claude/agents/<imya>.md`: YAML-шапка (`name` — латиницей,
`description` — по-русски, С ТРИГГЕРАМИ «когда вызывать» — по нему
работает автоделегирование; `tools` не указывать = все инструменты,
широкие полномочия; `model` не указывать = наследует сессию), тело —
системный промпт по-русски. Обязательные части промпта: роль и мандат;
«что читаешь первым» (всегда: CLAUDE.md + релевантные § plan.md);
процедура с конкретными командами и скриптами; формат вердикта
(`проходит | проходит с правками | СТОП/ВЕТО` + находки
[критично|важно|желательно] с файл:строка и способом починки);
красные линии (что агент не делает даже с широкими полномочиями —
обычно: не правит код без явного мандата «почини», не принимает
решений из §10, не выдумывает находок ради количества); взаимодействие
с другими агентами. Не плоди дублей — расширяй существующего.
Аудиторы ПРОВЕРЯЮТ пиксели и числа, а не верят коду и словам.

## Дизайн-концепция: Наведение резкости

Сайт ведёт себя как зрение, которому подобрали очки: контент проявляется
из расфокуса в резкость. Это системный язык ОБОИХ контуров.

### Словарь движения — ровно три глагола
1. `focusIn` — текст: opacity 0→1, y 24→0, blur(8px)→blur(0).
2. `maskLine` — заголовки: построчная маска (y 110%→0 в overflow-hidden).
3. `imageReveal` — изображения: scale 1.06→1 + opacity; для КАРТОЧЕК
   (не полноэкранных) допустим `imageRevealBlur` с blur 4→0.

### Бюджеты blur — эстетические (не перф-запреты)
- Жест появления/наводки (focusIn, титры, превью) — ≤8px.
- Анимируемый blur вне симуляторов и жестов появления — ≤5px, точечно
  на элементах (не на контейнерах секций).
- Фокус-идиома (соседи отступают) — ≤2px + приглушение.
- Полноэкранные фото НЕ блюрятся живым фильтром: тяжёлый статичный
  расфокус ЗАПЕКАЕТСЯ в ассет (sharp), тяжёлый живой — Kawase-шейдер
  на канвасе. Исключения: растровые снимки View Transitions (короткий
  переход, ≤8px); hero-фото — одноразовое появление blur 8→0.
- **Тяжёлая резкость снимается КАМЕРОЙ:** где кадр существует физически
  (rack-focus серии PDP, ступени тизера дропа) — используется съёмка/
  запекание, не фильтры.

### Семь законов движка (v1.1)
1. **Один владелец filter на элемент** — у узла ровно один источник
   CSS-фильтра; слои с разными фильтрами — разные узлы.
2. **Тяжёлый blur — не CSS** (см. бюджеты выше).
3. **Канвасы: DPR-кап 2 + renderScale** по EMA времени кадра —
   деградирует невидимое разрешение, никогда сам эффект.
4. **Один rAF-тикер** (Lenis autoRaf:false → эффекты → uniforms →
   рендер). Исключения: rvfc камеры, петли face-scan/frame-overlay.
5. **Единый шлюз ввода useGaze + useOpticalCapability** — новые эффекты
   не заводят своих matchMedia; `pointerFine` — признак ПРИРОДЫ ввода
   (drag, cursorTilt, magnetic), не перф-гейт.
6. **syncTouch у Lenis не включаем;** velocity — из шины Lenis
   (px/кадр), Motion useVelocity не подмешивать.
7. **ogl, не three** — для оптических шейдеров страниц (исключение
   этапа 15 — см. «Стек»).

### Подписные эффекты
Симулятор близорукости (шторка, честный непрерывный расфокус до −6 дптр
на Kawase; снап позиции и вибрация — на ступенях 0,5; CSS-фолбэк —
потолок 22px), WebGL-линза с рефракцией (Collections/Anatomy/фото PDP;
тач — long-press; **деградации без тупиков:** нет WebGL / потерян контекст /
не дошла текстура → прежняя CSS-лупа как РАБОЧИЙ эффект, не заглушка;
reduce → линзы нет вовсе. Текстура — только фото карточки: живой DOM и
FloatFrame в неё не попадают. Гравировка обода — DOM-SVG, не шейдер:
резка при любом renderScale. **Код расщеплён надвое:** в критическом пути
«/» живёт только триггер жестов, вся логика и ogl грузятся по первому
наведению — иначе линза стоила бы главной ~0,8 КБ gz на пустом месте),
«Зона ясного зрения» (Positioning), паспорт посадки
(камера). Один подписной эффект на блок; фокус-грамматика взаимодействия
подписным не считается.

### Запрещено навсегда (владелец)
Кислотный неон, частицы, бесконечно движущиеся градиенты, декоративные
3D-сцены, аляповатые свечения, волнистые разделители — удешевляют.
Плюс: таймеры обратного отсчёта, попапы, скидочные баннеры, очки/
бейджи-ачивки/прогресс-бары достижений, звук, e-mail-маркетинг,
конфетти. Разделитель по умолчанию — волосяная линия. Допустимы (решение
владельца): матовое стекло, СТАТИЧНЫЕ тональные градиенты-мосты, мягкий
кромочный блик. Критерий один — дорогой editorial-вид.

### Красный
- `#FD0000` (`brand`) — только графика: линии, eyebrow, крупный акцент.
- `#D40000` (`brand-deep`) — заливки кнопок и мелкий текст (контраст AA).

### Правило вечного движения
Бесконечных анимаций ровно ДВЕ (подсказка скролла hero, лента брендов) —
бюджет не расширяется. Всё остальное — отклик на жест, одноразовое
появление или привязка к скроллу. Любая бесконечная анимация обязана
останавливаться вне вьюпорта (IO) и в скрытой вкладке (visibilitychange);
новые канвасы спят так же.

### Доступность — выбор пользователя, не слабость устройства
`prefers-reduced-motion` (useReduceAfterMount / useReducedMotion /
CSS-медиа) — каждый эффект имеет reduce-ветку: статичный РЕЗКИЙ
функциональный контент. `prefers-reduced-transparency` → плотная заливка
стекла. ARIA, клавиатура, семантика не регрессируют. При снятии
perf-гейтов условие `desktop && !reduce` РАЗДЕЛЯЕТСЯ: perf-часть
убираем, reduce-часть сохраняем. Гидрация: ветвление по reduce — только
после маунта; статичные ветки задают стили ЯВНО ({opacity:1,
filter:"none"}) — Motion не стирает inline-стили.

## Мобильный паритет (заменяет все desktop-гейты)
Телефон получает ПОЛНЫЙ опыт: hero-раскадровку, фильтры и параллакс
оправ, фокальную плоскость (до 5px), velocity-резкость (шина Lenis
работает и на таче), motion-focus (до 3px), фокус-идиому (2px +
тач-эквивалент `.is-centered`), деко-оправы (уменьшенные размерными
классами). УХОДЯТ по этапам 1–2 plan.md через useOpticalCapability —
единую точку отката. UX-гейты ПРИРОДЫ ввода остаются: magnetic и
cursorTilt — pointer:fine; drag цитат — тач; гиро — только Android
(без permission-диалогов, iOS молча); вибрация — feature-detect,
троттлинг 40 мс, только через `src/lib/haptics.ts` (словарь: 10 мс
снап / 20 мс выбор / 30 мс успех); hoverOnlyWhenSupported — тач получает
эквиваленты.

## Парящие оправы (FloatFrame, mix-blend-mode: multiply)

### Физика (нарушение = сломанный сайт)
1. Blend смешивается внутри stacking context: transform/filter/opacity/
   mask/backdrop-filter/clip-path на ОБЁРТКЕ или ПРЕДКЕ — белый
   прямоугольник. Фон секции — ВНУТРИ трансформ-слоя; фильтры — только
   на `<img>` одним useMotionTemplate; новые слои — СОСЕДИ, не предки.
2. Белая точка — 4 рубежа: **закон меряет ВЕСЬ фон, а не рамку кадра**
   (`scripts/lib/white-point.mjs`: заливка от краёв; уровень фона —
   МЕНЬШЕЕ из двух: край кадра (p10 по краевым клеткам) и преобладающая
   масса фона (p75 по всем клеткам) — так пелена в глубине кадра не
   прячется за честной рамкой; тень под оправой в фон не входит).
   Рубежи: `ingest-frames.mjs` — обязывающий гейт приёмки кадров
   (`--verify` гоняется в день съёмки); отбор (gain >1.085 — брак,
   пустой слот лучше шва); `unoptimized` (WebP/AVIF сдвигает 255→254);
   пиксельный тест `cdp-audit.mjs` ±1 в покое и движении.
   ⚠️ `normalize-white.ps1` — быстрый СКРИНИНГ съёмочного дня (меряет
   рамку, без node); он не заменяет гейт: кадр с честной рамкой и серой
   глубиной пройдёт скрининг и будет отбракован приёмкой. Предохранитель
   `MaxGain` живёт ТОЛЬКО в PS1 — оба скрипта читают его оттуда.
   **Гейт обязан МОЛЧАТЬ, когда не может измерить.** Заливка встаёт на
   любой ступеньке яркости, и ступенька бывает не только у кромки оправы:
   светлая кайма по краю (перелив свипа, ретушь, кадр на белом холсте)
   останавливает её — «фоном» становится кайма, а серая глубина кадра
   получает «годен». Решает **БАРЬЕР, а не то, что за ним заперто**:
   заливку остановил материал оправы (барьер тёмный) — кадр честный;
   остановила ступенька экспозиции (барьер светлый ≥180) — фон НЕ измерен.
   ⚠️ Яркость запертой массы признаком быть НЕ МОЖЕТ: в «объект» попадают
   ИНТЕРЬЕРЫ ЛИНЗ (прозрачное стекло над свипом, 250–255), и живые deco-1/
   deco-3 при gain 1,0000 дают медиану объекта 254 — порог по ней забраковал
   бы годное макро. Два симметричных отказа: фон «перелез» на объект
   (>93 % кадра) ИЛИ замер не дошёл до фона (светлая масса >50 % кадра
   ЗА СВЕТЛЫМ барьером) → «НЕ ИЗМЕРЕН» + `--crop`, и это НЕ приговор кадру
   (в счётчик пересъёмки не идёт: фотограф, которого гоняют переснимать
   годное, перестанет верить и настоящему браку). Уверенное «годен» на
   невыясненном фоне — враньё, которое вскроется пиксельным аудитом,
   когда студию разберут.
   **Гейт проверяется САМ:** `--verify … --expect` на кадрах-ловушках
   (`_negative/whitepoint`, имя объявляет ожидаемый приговор:
   `ok-` / `brak-` / `nomeasure-`); расхождение роняет прогон. Без этого
   прибор однажды уже пропускал брак, честно рапортуя об успехе.
3. Multiply только затемняет — отбор матовых/тёмных/графичных оправ.
4. Размер — только размерными классами контейнера, НИКОГДА scale
   на обёртке. Тень — div с radial-gradient (×0.92 скорости; при
   cursorTilt слабеет), drop-shadow ЗАПРЕЩЁН. Статичные ветки задают
   стили явно. FloatFrame в WebGL-текстуры не включать.
5. **View Transitions НЕ сохраняют multiply:** морфы-перелёты blend-оправ
   только offwhite→offwhite.

### AlphaFrame (второй формат, этап 17)
PNG с альфой: normal blending, БЕЗ внутренней подложки, оптимизатор Next
РАЗРЕШЁН, drop-shadow легален; живёт на градиентах и ink. Своя приёмка:
обтравка, полупрозрачные кромки, отсутствие ореола. Multiply-рубежи
к альфе не применяются.

### Правила деко-оправ (v2.0)
aria-hidden у чисто декоративных; pointer-events-none, если не shoppable.
**Плотность вместо числа: ≤1 оправы в кадре одновременно, ≤2 на маршрут.**
Shoppable-деко допустимы: ярлык-СОСЕД (не обёртка), клик → PDP — ТОЛЬКО
собственные SKU (чужой мерч не кликабелен никогда). cursorTilt — у
«главной» оправы маршрута через useGaze. Мобила — уменьшенные, текст
не пересекают (проверка 360/390/430/1024–1920), z — под контентом, под
«Шкалой наводки». Левитация ЗАПРЕЩЕНА — вся жизнь от скролла и жеста.
«Путешествие» между секциями — монтажными склейками exitDefocus→entrance;
непрерывный полёт — отдельное решение владельца. Спящие фичи (draggable,
gyro, cursorTilt, shadow, exitDefocus) включает этап 17.

## Витрина (контур 2) — законы

1. **Сайт продаёт ВИЗИТ, не корзину.** Каждая коммерческая фича
   заканчивается салоном. Корзины/оплаты/аккаунтов нет.
2. **Один источник товарных данных — `src/content/frames.ts`** под
   zod-схемой; `scripts/validate-catalog.mjs` в приёмке каждого
   каталожного этапа (падает: битые пути, мм вне 40–62/14–24/120–155,
   дубли id/slug, протухшие остатки). Мм НЕ дублируются в BUILDERS.
   Гейт стоит в `prebuild` — невалидный каталог не доезжает до сборки,
   и **проверяет сам себя** (`--self-check`, 17 ловушек: имя объявляет
   приговор — урок этапа 10; у `bad-…` сверяется ещё и ПОВОД падения, иначе
   гейт «поймает» брак не за то, за что должен). Положительные ловушки
   обязательны: прибор, который только падает, мог бы браковать всё подряд.
   Тип `Frame` НЕ пишется руками: он выводится
   из схемы (`z.infer`), иначе тип и гейт разойдутся молча.
   ⚠️ **zod живёт только в `catalog/schema.ts`** (сборка и гейт). Витрина
   берёт помощники из `catalog/frame.ts` (без zod), а тип — типовым
   импортом: он стирается при сборке. Импорт `framePhotoPath` из схемы
   утащил бы валидатор на телефон клиента.
   **Жизненный цикл:** `draft` — тело товара есть, СВОИХ кадров ещё нет:
   черновик проходит мм-санити и НЕ рендерится нигде (так каталог
   наполняется с полки салона, не дожидаясь фотографа); `published` —
   только со своими кадрами, прошедшими `ingest-frames.mjs` (гейт требует
   файлы на диске в ОБЕИХ ширинах); `archived` — из листингов ушёл,
   прямая ссылка жива. Чужие каталожные кадры брендов не делают артикул
   `published` НИКОГДА. **Товар не выдумывается:** правдоподобный артикул,
   которого нет в наличии, дороже пустого каталога — за ним клиент приедет
   в салон и не найдёт оправу.
3. **Что где живёт и когда умирает:**
   - `optimist-fit` (localStorage) — выбор пользователя + квизовая
     само-декларация: {face(квиз), use, style, silhouette, frameId?,
     frameName?, color?, price?, recommendation?(квиз), code?(квиз),
     source, ts}; каждая запись диспатчит `optimist-fit-updated`.
     ⚠️ `code` здесь — код РЕКОМЕНДАЦИИ квиза, не одноимённый камерный код
     формы лица (тот живёт в `fit-session`). Граница держится на ВХОДЕ:
     `writeFit` санитизирует записи `source:"camera"` по белому списку
     (silhouette/frameId/frameName/color/price), `readFit` — ещё и вычищает
     с диска «отравленные» записи прежних сборок;
   - `fit-session.ts` (in-memory) — ВСЁ камерное: face/code/secondary/
     PD/мм/widthStep; умирает с вкладкой;
   - `optimist-shelf` (localStorage, ≤7 позиций, TTL 30 дней) —
     только {frameId, ts};
   - Telegram-заявка — имя, телефон, номера оправ, салон, честный
     источник; НИКОГДА не камерная классификация;
   - аналитика — только имена событий, никогда содержимое подбора.
4. **Персонализация после маунта:** SSG-разметка нейтральна; бейджи,
   предвыбор фильтров, полка — post-mount; cdp-hydration в приёмке.
5. **Честность коммерции:** дефицит только честный; обещание сайта
   публикуется после операционного «да» людей (до него — «подготовим
   к визиту», «обычно есть в …», «расскажем в канале»); наличие —
   мягкая разметка; тизер дропа — по ручному статусу far/near/live,
   не по дате; back-in-stock/листы — подписка на Telegram-канал;
   recall — локальный .ics; серверных баз ПД нет.
6. **Бейджи посадки:** размерный «ваша ширина» — геометрия, публикуется
   сразу; стилевой fitsFaces — только после подписанного
   `docs/optometrist-review.md`. Тексты — констатация размера,
   не обещание посадки; «ориентир, не рецепт» — всюду.
7. **Хром route-aware:** якоря шапки — `/#…`; SectionRail только на «/»;
   на маршрутах витрины — крошка-волосок + мобильная навигация каталога;
   shelf-tray = хром (вне бюджета контентного стекла), грузится лениво.
8. **Прелоадер «op»:** ТОЛЬКО первичная загрузка главной (заход извне /
   reload на «/»); при первом маунте вне «/» decision кэшируется «done» —
   НИКОГДА посреди SPA-сессии. Знак, глаза, зрачки, моргание — авторские,
   НЕ менять; хвост растворения — эстафета фокуса в hero; страховки
   2.2 с / CSS ~5 с остаются.

## Примерка и камера

### Приватность — закон (исполнять буквально)

стирание (stopStream, clearRect, обнуление ландмарок и окна усреднения);

явный выбор пользователя (silhouette/frameId/frameName/color); всё
камерное — только fit-session (см. «Витрина» п.3). Share-кадры —
локальный canvas, только руками пользователя. Consent-экран не
пропускается никаким интентом.

### Ассеты — локально
WASM → `public/mediapipe/wasm/` (simd/nosimd), модель
`face_landmarker.task` → `public/mediapipe/`; ноль внешних обращений.
Ассеты коммитятся. Пакет и модель грузятся ТОЛЬКО по клику «Включить
камеру» (dynamic ssr:false) — бандл «/» не растёт.

### Дорожная карта точности (2D → 2.5D → 3D)
Матрица позы `facialTransformationMatrixes[0]` читается в
`latestRef.matrix`; сглаживание — `one-euro.ts`; метрический масштаб —
радужка ⌀≈11,7 мм; поза — `pose.ts` (одна ось на все горизонты).
2.5D: проекция лекал через матрицу, псевдо-окклюзия дужек по контуру
щеки, фото-спрайты реальных SKU — вечный фолбэк. 3D (этап 15, гейт):
three в lazy-чанке, occluder depth-only, IBL с фотосессии, GLB-приёмка
(иерархия front/temples/lenses/nosepads, пивоты на петлях, origin —
переносица, метры в натуральную величину, extras: мм, ≤20k треугольников,
KTX2+Draco). Деградации без тупиков: 3D→2.5D→квиз.
Карты «форма→оправа» и тексты fit-скора — `// ПРОВЕРИТЬ ОПТОМЕТРИСТАМИ`,
публикация только после подписи.

## Стекло и переходы

### Система стекла
Рецепты в `globals.css` (@layer components): `.glass` (светлый хром,
карточки), `.glass-dark` (тёмный тинт поверх фото), `.glass-on-dark`
(светящаяся плёнка на ink), `.glass-sheen` (кромка-блик; следует за
useGaze transform-ом). Глубина 16–24px + saturate — СТАТИЧНО; радиус
backdrop-blur НИКОГДА не анимируется (анимируются opacity/mask).
Бюджет: ≤2 КОНТЕНТНЫХ поверхности в кадре; хром навигации (шапка,
кнопка-линза, shelf-tray) — вне бюджета. Деградации обязательны:
@supports без backdrop-filter → плотная заливка; reduced-transparency →
плотная заливка. ⚠️ Стекло — сосед FloatFrame, никогда не обёртка.

### Переходы маршрутов
View Transitions (next-view-transitions) — рэк-фокус растровыми
снимками; главная участвует (живой DOM не оборачивается — multiply цел);
хром — собственные view-transition-name; морф оправ —
`vt-frame-<id>`, только offwhite→offwhite. `template.tsx` — фолбэк без
VT; при активной VT возвращает children БЕЗ анимации (нет двойного
наведения). Маршрут «/» в motion-обёртку не оборачивается НИКОГДА.
Speculation Rules prerender — с гейтом `document.prerendering`
(до активации ни кадра тяжёлых ассетов). FocalSeam — scroll-scrub швы
на стыках глав главной, метку провожает useGaze; reduce — статичная метка.

## Фото и лицензии — «контракт кадра»
Эффект строится на КОНТРАКТЕ КАДРА: техбриф `docs/photo-brief.md` —
часть канона; каркас строится на первых реальных кадрах, слоты
добираются конвейером `ingest-frames.mjs`. **Packshot: фотограф сдаёт
ДЕСЯТЬ кадров, на сайт уходят СЕМЬ** (front, quarter, side, folded, top,
macro-1, macro-2); `front-top`, `side-ortho`, `front-ortho` — референс
и чертёж миллиметров: сдаются обязательно, в веб не публикуются никогда.
Забракованный артикул не оставляет кадров в `public/`. Blend-кандидаты — только
через `ingest-frames.mjs --verify` в день съёмки (gain >1.085 — брак);
`normalize-white.ps1` — быстрый скрининг, гейта НЕ заменяет. RAW хранится
всегда. `photos.ts`/`frames.ts` НИКОГДА не лгут об источнике и авторе
кадра; чужие каталожные кадры брендов не публикуются и не кликабельны.
Согласие на образ клиента — письменно (`docs/consent-photo.md`) ДО
публикации. **Гейт (как у `optometrist-review.md`): форма — ЧЕРНОВИК, пока
её не утвердил юрист владельца по ЗРУ-547; до утверждения людей не снимаем
и кадры с узнаваемыми лицами не публикуем.** Сканы подписанных согласий —
в `docs/permissions/` (в git НИКОГДА: это ПД, папка в `.gitignore`). Секвенции —
через `build-seq.mjs` (падает при превышении бюджетов). **Числа веса и ширины
живут ТОЛЬКО в `docs/perf-budgets.md`** — скрипты читают их оттуда
(`scripts/lib/canon.mjs`), дублировать в коде запрещено: дубль ширины уже
расходился с реестром молча, и «десктопный» набор собирался мыльным, а манифест
об этом лгал. **Ширина — КОНТРАКТ, а не потолок:** недомерок не ужимается тихо,
он падает. Вес — наоборот: **превышение веса не пересъёмка** (ширина, качество
или осознанно поднятый потолок), фотографа за вес не гоняют.

## Невидимая геймификация и награда
Награда — момент ИЛИ материальная память (полка, паспорт посадки,
каталожная карточка — утилита и документ, не achievement). Очки, бейджи,
прогресс-бары — запрещены навсегда. Единый success-момент — «щелчок
фокуса»: пауза-вдох 300–400 мс → наведение на резкость + haptic 30 мс.
Дофаминовые пики живут в серотониновой раме: тишина, воздух, волосяные
линии вокруг.

## Типографская гигиена русского текста
«Ёлочки», длинное тире « — », неразрывные пробелы после коротких
предлогов/союзов и в связках («20 минут», «−6 дптр», «№ 14», «3 дня»,
«7 из 30») — закон ВСЕГО контента, включая Telegram-шаблоны заявок,
.ics-тексты, OG- и alt-тексты. Правится в строках контента,
не рантайм-регэкспами. Мотив таблицы Сивцева работает РЕДКОСТЬЮ.
Живой статус «Открыто · до …» — без пульсации, нейтральная строка
до маунта.

## Приёмка — по приборам, не на глаз
Инструменты в repo (нужен `npm run dev` на :3000): `shot-site.mjs`
(кадры, env SHOTS, mouse/mobile; `clickAt` — клик В ТОЧКУ элемента:
`clickOn` бьёт в центр и не несёт координат, а состояние ползунка/шторки
задаётся тем, ГДЕ нажали), `cdp-audit.mjs` (белая точка ±1,
desktop+mobile), `cdp-whitepoint.mjs`, `cdp-hydration.mjs`,
`diag-firstload.mjs`. ⚠️ **`cdp-hydration.mjs` ходит по СПИСКУ маршрутов
(`--routes=/,/privacy`, дефолт — они же) — каждый этап витрины ОБЯЗАН дописать
свои.** Прибор, знавший только «/», молча выдавал «чисто» по всему сайту:
маршрута, которого он не открывает, для него не существует. Он же сверяет
HTTP-код документа: страница 404 у Next — это тоже живой `<main>` с текстом
по тому же адресу, и без кода ответа опечатка в имени маршрута возвращалась
«чистой гидрацией» непроверенной страницы. Дев-сервер НЕ нужен ни конвейеру
ассетов, ни гейту каталога: `ingest-frames.mjs` (приёмка сдачи фотографа),
`build-seq.mjs` (секвенции; потолки читает из `docs/perf-budgets.md`, падает
при превышении), `make-pilot-delivery.mjs` (пилотная сдача с намеренным браком),
`validate-catalog.mjs` (`npm run validate:catalog`; в `prebuild`, плюс
`--self-check` — 17 ловушек в `scripts/fixtures/catalog/`),
`check-bundle.mjs` (`postbuild`: стережёт zod и роутер в клиентских чанках),
`npm run test:lib` (юнит-тесты чистых функций `src/lib` — геометрия паспорта
посадки и классификатор формы лица; дев-сервер НЕ нужен). ⚠️ Список тестов
берётся С ДИСКА (`scripts/run-lib-tests.mjs`), а не перечислением: прибор,
знающий один файл, — это прибор, который лжёт. `face-shape.test.ts` пролежал
живым, но НЕ ПОДКЛЮЧЁННЫМ НИ К ЧЕМУ — мёртвый тест хуже отсутствующего, он
создаёт иллюзию покрытия. Пустой прогон = провал, а не успех.
**Гейты доказываются ПАДЕНИЕМ, а не успехом:** прибор, который только «успешно
проходит», однажды пропустил брак, честно рапортуя об успехе.
⚠️ **Совпадение замеров серии ДО ПОСЛЕДНЕГО ЗНАКА — это «НЕ ИЗМЕРЕНО», а не
«разницы нет».** Если прибор прогнал серию положений и получил одинаковые
числа, вероятнее всего он мерил ОДНО И ТО ЖЕ МЕСТО. Так таблица непрерывности
этапа 6 отрапортовала «Δ = 0, непрерывно» на плотном экране: окно замера
задавалось в CSS-пикселях, а снимок приходит в физических, и замер уезжал
в угол страницы. Предохранитель обязателен в каждом приборе, который сравнивает
серию: вырожденная серия роняет прогон, а не проходит его.
⚠️ **Непрерывность и другие свойства ЧИСЛЕННОЙ МОДЕЛИ доказываются чистой
функцией и юнит-тестом, а не браузером.** Замер в Chrome дорог, требует dev,
зависит от кадра и сам однажды соврал. Если поведение выводится арифметикой —
оно выносится в `src/lib/*.ts` с тестом (`npm run test:lib`), и тест ОБЯЗАН
содержать негативный контроль: тот же критерий, прогнанный по ПРЕЖНЕЙ, заведомо
сломанной формуле, обязан её забраковать. Иначе тест доказывает лишь то, что
он не падает. ⚠️ И помни границу: такой тест доказывает модель, а не пиксели.
Расхождение модели с замером означает, что неверна модель.
⚠️ **Канвас, подменяющий или продолжающий DOM-слой, обязан доказать совпадение
на ВЫКЛЮЧЕННОМ эффекте.** Прежде чем мерить эффект, замеряется passthrough:
при нулевой силе канвас обязан быть пиксельно неотличим от DOM под ним —
кадрирование (`object-fit`), масштаб, цветовое пространство, гамма. Замер
ведётся на ОДНОМ И ТОМ ЖЕ участке кадра переключением слоя
(`visibility:hidden` на канвасе), а НЕ сравнением двух сторон границы:
по разные стороны шва лежат разные куски изображения, и такой замер меряет
сюжет, а не шов. Так этап 6 полгода не видел, что шейдер натягивает ПОЛНЫЙ
кадр поверх `object-fit: cover` (Δ до 97,8 на выключенном эффекте) — глазами
это маскируется размытием. Причина считается доказанной только каузальной
пробой (принудительный `object-fit: fill` обрушил Δ до 0,30), а не выведенной
из рассуждения.
⚠️ **Ступень эффекта не имеет права менять картинку скачком.** Если у эффекта
есть подписанные пользователю ступени (дптр, мм, проценты), внутренние
переключения машинерии (уровни цепочки FBO, смена разрешения, ветка
рендера) обязаны быть непрерывны ВНУТРИ подписи: два соседних положения
с одинаковым `aria-valuenow` обязаны выглядеть одинаково. Проверяется
таблицей метрики по мелкому шагу ползунка через каждую внутреннюю границу,
а не на глаз.
⚠️ **`npm run build` и живой `npm run dev` делят папку `.next` и топят друг
друга:** сборка при работающем dev падает выдуманными ошибками (ложное
«Failed to collect page data for /api/booking» — кода не касалось). Меряешь
вес — гаси dev.
⚠️ **Вес меряется `next build`, а не на глаз, и на КАЖДОМ шаге витрины:**
один импорт `next/link` в компонент главной стоит 9 КБ критического пути
(docs/perf-budgets.md) — глазами это не видно.
⚠️ **Разрез «разметка / машинерия» — как этап платит за свой вес** (закон,
выведен этапом 6). Компонент, утяжеливший критический путь, режется НЕ по
файлу, а по границе. На сервере остаётся ОБОЛОЧКА: LCP-кадр настоящим `<img>`,
зарезервированная CSS-пропорция контейнера, контентные подписи и ARIA-каркас
управления в ОДНОМ экземпляре (живая часть правит его атрибуты императивно —
второго `role="slider"` не заводит, иначе у скринридера два ползунка на один
кадр). Лениво уезжает МАШИНЕРИЯ: обработчики жеста, клавиатура,
motion-значения, GL-слои. Вес живёт в машинерии, а не в разметке — поэтому
возвращаются килобайты, а не байты. **`ssr:false` на весь файл ЗАПРЕЩЁН:** он
выносит из HTML кадр и высоту — пустая коробка на LTE и прыжок вёрстки при
гидрации, то есть размен байтов на регрессию метрик. Резать имеет право только
этап-владелец модуля (охота за байтами по чужому коду запрещена), ПОСЛЕ шагов,
задающих форму компонента (иначе режешь дважды), и выигрыш ИЗМЕРЯЕТСЯ: сама
glue `next/dynamic` стоит сотни байт и однажды съест то, ради чего резали.
⚠️ **CLS такого разреза доказывается КОНСТРУКЦИЕЙ, а не замером:** высота
контейнера задана CSS-пропорцией, ВСЕ узлы ленивой части — `absolute` внутри
него, блоки переменного текста держат фиксированную высоту. Замер — одна
выборка на одной машине; конструкция закрывает все. Прогон Lighthouse такой
разрез не отменяет, но и не является его доказательством.
